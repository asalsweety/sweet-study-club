# Greenfield UX review and redesign

Date: 2026-11-08. Scope: the existing Persian web application, reconsidered around the learner's next action. The initial source-code audit was followed by Playwright functional checks and screenshot review at the user's request. No Computer Use was used.

## Findings and implemented decisions

1. **Account entry — repaired.** `src/App.tsx` formerly prioritized local onboarding state over the server session. Returning users could hit welcome and introductory screens before authentication was checked. Startup now resolves the session first, uses one account form, and preserves protected destinations until login succeeds. Old `/onboarding` links redirect to home after authentication.
2. **Authentication errors — repaired.** Better Auth's `{code,message}` failures were not recognized by the shared API envelope parser. Known credential errors and rate limits now receive useful Persian messages. Network failures are not interpreted as signed-out sessions. A profile failure offers retry instead of a permanent loader. Any API 401 rechecks the server session.
3. **Signup and logout — repaired.** Account creation and login are explicit stages inside one screen. If creation succeeds but login fails, the form switches to sign-in so retry does not recreate the account. Successful login clears old account caches and verifies the server session. Logout clears private caches only after server success; errors remain visible and leave the existing session intact.
4. **Today and study — rebuilt.** One primary start/resume action leads the dashboard, alongside the daily goal. Supporting metrics, the club schedule, and planner/learning shortcuts follow. Timer loading and failure cannot masquerade as an idle timer. The start dialog has named controls and selected states; unavailable scheduled sessions are explained. Active sessions expose pause/resume failures.
5. **Navigation — rebuilt.** Four core destinations (Today, Plan, Learn, Progress) work on desktop and mobile. A mobile More menu exposes account, friends, league, shop, and authorized admin tools. Account settings are consistently reachable. Logout has one home, in account settings. A skip link provides keyboard access to the main content.
6. **Planning — improved.** A page-level purpose and create action precede the calendar. Empty days explain what to do next. Calendar buttons expose full dates and selected/today states. Edit controls remain visible rather than requiring hover. Removal asks before deleting a plan item; mutation and load errors are visible.
7. **Learning, progress, community, shop — unified.** Shared headings, paper surfaces, spacing, calmer typography, and button styles carry across the product. Loading/error distinctions prevent failed queries from looking like empty results. Learning retains its existing question bank, attempts, review, notes, and advanced tools. Rankings retain opt-in behavior.
8. **Account — reorganized.** Settings, subjects, achievements, and reports have independent URL-addressable sections. Appearance controls are in settings rather than competing with study on every page. Editable profile fields use an explicit Save action with feedback; immediate toggles are described as autosaving. Subject actions have larger targets and readable foregrounds.
9. **Admin — reorganized.** Overview, schedule, learning content, members, and products/messages are separate sections rather than a single long page. Existing authorization and backend operations remain in force.
10. **Visual system — replaced.** Warm ivory, forest green, quiet borders, restrained shadows, consistent corner sizes, and reduced heading weight replace oversized gradient-heavy cards. Dark mode and all existing palettes retain semantic tokens. Mobile navigation respects safe-area insets; dialogs scroll within viewport height; focus clocks scale down on narrow screens. Print hides navigation and action controls.

## Evidence and limits

Evidence includes the current checkout's routing, auth client, query lifecycle, components, styles, and Playwright checks against a local Worker with an isolated D1 database. Synthetic accounts exercised real authentication and API calls. Screenshots cover desktop (1440px), mobile (390px), and narrow mobile (320px), including dark mode, dialogs, navigation, the helper, and admin. Existing unrelated working-tree changes were preserved.

Password recovery still requires a configured mail provider; the redesign does not advertise an unavailable recovery action. Screen-reader behavior, real device keyboards, and exhaustive contrast checks remain unverified.

## Verification

Completed: lint, TypeScript checking, 108 tests in 22 files, production Worker/PWA build, artifact checks, performance budgets, and Cloudflare dry run. Account-entry JavaScript: 397,417 bytes (127,650 gzip); CSS: 96,086 bytes. Tests used a workspace-local temporary directory because the Windows sandbox denied Vite cache renames in the system temp directory. The auth policy fixture now mocks the Better Auth constructor while testing the actual configuration and role hook, avoiding accidental adapter initialization against its empty D1 stub.

Regression coverage in `src/app/entry-flow.test.tsx` exercises session-first entry, deep links, expired sessions, and connection/profile errors by rendering the real App with controlled query states. `src/app/auth.test.ts` exercises actual auth requests, server error formats, and successful/failed logout cache behavior. Existing API, timer, learning, permissions, and theme suites are retained. The performance report follows AuthScreen rather than the retired Welcome entry graph.

Playwright caught a session observer lifecycle bug that unit request checks had missed: clearing the entire query client detached the mounted session observer, leaving the account screen visible after successful authentication. Account transitions now keep that query alive while clearing other account data. A QueryObserver regression test covers both sign-in and sign-out transitions. Browser checks also cover invalid credentials, failed logout, session persistence across reload, protected deep links, timer pause/resume/finish, planner completion persistence, profile saves, and mobile navigation.

Screenshot review caught progress heatmap page overflow and a duplicate translation in the shared dialog animation. The heatmap now scrolls within its card, dialog animations preserve their centered placement, and finish-session counters fit narrow screens. The dialog grid constrains its contents so they cannot widen the panel's inner column. Browser assertions check page width, dialog viewport bounds, and internal dialog overflow. Local screenshots and reports are in the ignored `test-results/playwright/` directory.

## Release

Deployed to the existing Cloudflare production Worker and custom domain on November 8, 2026, version `9cc3480b-0e9a-488d-8c22-91420cab747c`. Cloudflare reports 100% traffic on that version. Live HTTP checks through workers.dev verified the release asset fingerprint, health/readiness, signed-out session response, and protected profile rejection. Public browser checks could not complete because connections from this workstation timed out or reset. See `docs/cloudflare-production.md` for the exact verification scope and rollback information.
